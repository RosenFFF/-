# 丝路智审 · 项目作品说明文档

> 参赛编号：＿＿＿＿（匿名）｜编制参照 GB/T 8567-2006《计算机软件文档编制规范》｜v0.1 初稿，TODO 为待补实测数据

## 1 引言
### 1.1 编写目的
说明「丝路智审」的需求、设计、模型协同、模型优化、测试与部署，供评审核验作品与代码一致性。
### 1.2 背景
一带一路与金砖国家贸易规模持续增长，外贸中小企业需处理发票、装箱单、原产地证、报关单等多语种单证，涉及关税、原产地规则（如 RCEP、中国—东盟自贸协定）、禁限目录等大量规则。人工审核慢、易错，退单与滞港带来直接损失。
### 1.3 术语
OCR、LLM、RAG、Embedding、Reranker、HS 编码、原产地证、RLS、AIGC 标识。
### 1.4 参考资料
技术规程 §八 所列 GB/T 8567-2006、GB/T 15532-2008、ISO/IEC 25010:2011、GB/T 45654-2025、GB 45438-2025 等。

## 2 需求说明
### 2.1 用户与角色
合规员（上传、审查、追问、修正字段）、安全管理员/审计员（全局审计与看板）、管理员（用户与配置）。
### 2.2 功能需求
| 编号 | 功能 | 说明 |
|---|---|---|
| F1 | 单证上传 | PDF/PNG/JPEG，≤10MB、≤10 页，加密落盘 |
| F2 | OCR 识别 | 多语种文本、坐标、置信度，逐页 |
| F3 | 字段抽取 | LLM 结构化输出，每个字段带页码与 bbox，点字段高亮原件 |
| F4 | 合规审查 | 规则引擎 + RAG 条款检索 + LLM 推理，风险分级并引用条款 |
| F5 | 多语种解释与追问 | 中/英/俄/越/葡/阿，SSE 流式，带引用 |
| F6 | 人工复核 | 修正字段后重审，全程留痕 |
| F7 | 安全审计看板 | 越权、注入拦截、脱敏计数、模型调用、哈希链校验 |
| F8 | 模型链路展示 | `/system/models` 实时显示各模型状态与降级级别 |
### 2.3 非功能需求（对照 ISO/IEC 25010）
性能：单页单证端到端审查 P95 ≤ TODO 秒；可靠性：断网可继续运行；安全性：见安全说明书；易用性：中英界面切换；可移植性：Docker Compose 一键部署。

## 3 概要设计
### 3.1 总体架构
前端（React/TypeScript，验单台界面）→ API（FastAPI）→ Worker（arq）→ 模型层（本地 OCR/Embedding/Reranker + 云端/本地 LLM）→ 数据层（PostgreSQL + pgvector、Redis、加密文件卷）。
### 3.2 模块划分
core、security、api/v1、services、ai（ocr/llm/rag/prompts/guards）、rules_engine、db、workers、audit（详见 architecture.md §3）。
### 3.3 接口设计
OpenAPI 3.1 契约 `docs/api.yaml`：统一错误格式（`code`）、异步任务 202 + 轮询、追问 SSE（`delta`/`citation`/`done`）、归一化 bbox。
### 3.4 数据设计
主要表：tenants、users、documents、ocr_results、document_fields、reviews、review_messages、rules、rule_chunks、model_calls、audit_logs。

## 4 模型协同链路
| 序 | 模型类别 | 选型 | 部署 | 作用 |
|---|---|---|---|---|
| 1 | OCR | RapidOCR（PP-OCRv4 ONNX） | 本地 CPU | 单证文字与坐标识别 |
| 2 | LLM | DeepSeek-V3（主）/通义千问 qwen-plus（备）/Qwen2.5-7B Q4（离线） | 云端+本地 | 字段抽取、合规推理、多语种解释、追问 |
| 3 | Embedding | BGE-M3 | 本地 | 规则条款多语种向量检索 |
| 4 | Reranker | bge-reranker-v2-m3 | 本地 | Top-20 → Top-5 精排 |

链路：上传 → OCR → 脱敏+注入检测 → LLM 抽取（JSON Schema）→ 规则引擎 → 向量召回 → 重排 → LLM 推理（仅可引用给定条款）→ 引用校验 + AIGC 标识 → 报告 → 追问。所有调用写入 `model_calls`，现场可逐条核对。

## 5 模型优化设计
### 5.1 OCR 优化
图像预处理（纠偏、去噪、二值化）、多语种识别模型按单证语种选择、低置信度字段标记复核；指标：字段级准确率 TODO。
### 5.2 LLM 提示与结构化
版本化提示模板、少样本示例、JSON 模式 + Pydantic 校验与一次重试、单证类型专用抽取 Schema；指标：字段抽取 F1 TODO。
### 5.3 RAG 优化
条款级切片（保留条款号与出处）、多语种查询改写、混合检索（向量 + 关键词 TODO）、重排、引用约束；指标：Recall@5、引用准确率 TODO。
### 5.4 成本与时延
本地承担 OCR/向量/重排，云端只处理脱敏文本；缓存规则检索；token 配额；指标：单份审查成本与 P95 时延 TODO。
### 5.5 鲁棒性
四级降级（L0 正常 / L1 切备用云端 / L2 本地 LLM / L3 规则兜底），每级真实运行。
### 5.6 评测方法
参照 GB/T 45288.2-2025 评测思路，自建评测集（脱敏样例单证 N 份 TODO），对比基线（直接 LLM、无 RAG、无重排）的消融实验表 TODO。

## 7 部署与运行
环境：8 核 16GB 演示机（参考）、Docker；步骤：配置 `.env`（密钥不入仓）→ `docker compose up -d` → 预热模型 → `/readyz` 检查；离线：预先拉取镜像与本地模型，`ollama` profile 可选。

## 8 创新点
1. 面向一带一路/金砖的多语种跨境单证合规审查，场景稀缺且贴合赛事主题。
2. 「规则引擎先判 + 条款约束 RAG + 引用校验」三道保险，结论可溯源、抗幻觉。
3. 点字段即高亮原件对应区域，模型链路证据可视化。
4. 安全内生：出域脱敏可视化、哈希链审计可现场验证、越权实时上看板。
5. 断网四级真实降级，现场可演示。

## 9 应用价值
降低外贸中小企业单证退单与滞港风险，缩短审核时间（目标指标 TODO）；可扩展至更多国家规则库与报关代理、外贸综合服务平台；数据不出本地，满足企业保密要求。

## 10 总结与展望
