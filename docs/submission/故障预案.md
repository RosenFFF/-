# 丝路智审 · 演示故障预案（M3 草稿）

> 匿名文档。目标：决赛/彩排时任一依赖失败，**10 秒内切档**，不现场改代码、不读密钥、不把替身说成真验收。  
> 与路演脚本配合；控制台口令与密钥只在演示机本地保管，不入本文、不入仓。

## 1. 档位定义
| 档位 | 含义 | 可演示内容 | 口头说明模板 |
|---|---|---|---|
| L0 | 全量在线 | OCR + 云端 LLM + RAG + 审计 | 「当前为完整在线档」 |
| L1 | 备用云端 | 主 LLM 熔断后切备用厂商 | 「主模型不可用，已切备用云端」 |
| L2 | 本地 LLM | 断网/云端全挂，走本地 Qwen 等 | 「离线本地模型档」 |
| L3 | 规则兜底 | 无可用 LLM，仅规则引擎 + 已缓存检索 | 「模型不可用，确定性规则兜底，结论需人工复核」 |
| L-demo | 受控回放 | 仅当基础设施崩溃且无法在时限内恢复 | 「基础设施故障，展示预置脱敏样例与审计链校验；不宣称现场模型推理」 |

禁止：用 FakeLLM/MOCK 红条界面冒充 L0；禁止隐瞒降级。

## 2. 开场前 3 分钟检查（失败即预降级）
1. `GET /readyz`（或等价健康检查）全绿。  
2. `/system/models`：OCR / Embedding / Reranker / LLM 状态可读。  
3. 用合规员账号登录 → 打开审计看板（管理员窗）确认 WebSocket/轮询正常。  
4. 上传 1 页样例，确认 OCR 返回非空。  
5. Redis/限流：故意触发一次只读探活（勿在开场刷爆配额）。  
6. PostgreSQL：简单租户内查询成功；若 RLS 验收未完成，**不要**向评委宣称「RLS 已官方验收」。

任一步失败：按 §3 决策树降到可支撑的最高档，并在开场 15 秒内说明。

## 3. 决策树（现场）
```
/readyz 失败？
  ├─ PG 挂 → 尝试重启 compose/demo-env（≤30s）→ 仍失败则 L-demo（审计链用预置库快照）
  ├─ Redis 挂 → 限流 fail-closed 可能 503：宣布「限流降级/只读演示」，避免高频写；追问可切 L3
  └─ 仅模型红 → 进入模型分支

模型分支：
  云端主模型超时/5xx → L1 备用
  备用仍失败或已断网 → L2 本地
  本地加载失败/OOM → L3 规则兜底
  以上皆不可用 → L-demo
```

## 4. 分场景操作卡

### 4.1 离线 / 断网
- 动作：拔网或关 Wi-Fi → 刷新 `/system/models` → 确认本地 OCR/向量仍可用。  
- 预期：新审查走 L2；报告角标或文案含「离线/本地」。  
- 失败：立即 L3；展示规则命中与「需人工复核」。  
- 话术：「原件从未出域；断网后推理留在本地。」

### 4.2 模型不可用（超时、配额、内容过滤）
- 动作：不要重试超过 1 次；看熔断提示；切备用或本地。  
- 追问 SSE：若中途断开，展示已缓冲片段 + 友好错误，不刷新丢上下文（若 UI 支持续传则点续传一次）。  
- 话术：「熔断保护配额与稳定性，结论可回退到规则引擎。」

### 4.3 限流 429
- 动作：停止连点；展示 `Retry-After` 与审计中的限流事件；换管理员窗继续安全核验项。  
- 勿：现场改大限额或关 Redis。  
- 话术：「用户+IP 双维限流，防刷与防 token 耗尽。」

### 4.4 PostgreSQL 不可用 / 迁移漂移 gate
- 症状：启动失败、`deployment blocked`、页面 5xx。  
- 动作：≤30s 内按演示机文档重启 DB；**禁止**现场 `ALTER POLICY` 放宽 RLS。  
- 仍失败：切 L-demo；可演示 `/audit/verify` 于预置数据，或展示自扫描报告与代码结构。  
- 话术：「启动 gate fail-closed，宁可拒绝启动也不带病跑。」

### 4.5 Redis 不可用
- 预期：限流组件 fail-closed（503 `RATE_LIMIT_UNAVAILABLE` 类）。  
- 动作：减少写路径；优先做权限 403、脱敏面板、verify 等读多核验；说明 Redis 恢复前不开放高频模型调用。

### 4.6 前端白屏 / 构建档错误
- 动作：硬刷新一次；切备用浏览器窗口（预开）。仍失败则投屏预置只读页或安全说明书 PDF，改为「安全与架构讲解」抢回安全分与展演分。  
- 检查：生产构建须通过 no-mock / no-demo 门禁；现场不得启 MOCK 红条。

### 4.7 注入演示「没命中」
- 动作：换备用注入样例（编码绕过/角色扮演）；若仍未命中，展示单元测试报告与审计中历史拦截记录，诚实说明规则库持续扩充。  
- 勿：现场改正则。

## 5. 时间盒
| 故障 | 最大自救 | 超时动作 |
|---|---|---|
| 服务重启 | 30s | 降档或 L-demo |
| 模型切换 | 15s | 下一档 |
| 前端恢复 | 10s | 备用窗/PDF |
| 任何现场改配置 | 0s（禁止） | — |

## 6. 恢复与收尾
- 演示结束后再恢复 L0；勿在问答期重启集群除非评委要求。  
- 记录实际使用档位、失败点、耗时，回填评测表「待补」项。  
- 密钥泄漏怀疑：立即轮换演示密钥（仅演示机），并重新跑 gitleaks；详情不进公开文档。

## 7. 与评分的关系
- 功能分：L2/L3 仍可展示主流程与规则结论，但须标明档位。  
- 安全分：403、脱敏、429、`/audit/verify`、自扫描零高危在基础设施部分可用时优先保证。  
- 模型优化分：机制（重排、引用约束、降级链）可讲；无实测表则明确「指标待补」。  
- 否决项规避：永不假造模型调用；永不展示含学校/姓名/个人联系方式的界面或文档。
