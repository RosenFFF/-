## 3 操作卡
### PG/启动门禁失败
检查回环监听、认证与角色、readyz 和脱敏日志；按已有运维文档恢复。S 曾因缺失目录启动失败，原因尚未确定。禁止 initdb、重置 WAL、放宽 RLS、切 owner 或绕过启动检查。恢复失败则只读回放，不静默切 SQLite。历史完整性与自启另行核验。

### Redis 失败
保持限流 fail-closed；检查回环服务与配置，不关限流、不切 fakeredis。读接口也先核验可用性，不能承诺故障下仍正常工作。恢复后再测试写入和模型配额路径。

### 模型健康异常
核对实际 system/models 与最小调用结果；配置名或模型列表本身不能替代推理验证。健康别名探测已合入 main；不得为“绿灯”删验证。被网络拦截的模型下载不重试、不绕过；不用空库存承诺本地降级。

### SSE MODEL_UNAVAILABLE
HTTP 200 不是业务成功。按事件检查 error/done，显示失败并保留上下文。F 已有此错误 UI 证据。宽泛追问越界引用的根因已修复（见上）；再出现时先看诊断阶段，不能写成网络或密钥失效；独立上游 SSE 正常不代表应用正常。保留脱敏错误码/trace/问题类别，转报告与人工复核，不把换简单问题说成修复。

### 前端/生产构建失败
使用 no-mock/no-demo 检查；无法恢复则展示标明环境的历史证据或文档。F 的开发服务器/SQLite/fakeredis 截图不可冒充生产真实模型链路。

### 凭据或身份信息泄漏风险
立即停止公开展示，凭据只在私有运维通道处理和轮换，不抄进日志/工单/证据。复核泄漏范围并运行 gitleaks。所有公开材料保持匿名。
