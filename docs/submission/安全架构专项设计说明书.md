## 1. 概述

### 1.1 系统简介
「丝路智审」是面向一带一路/金砖贸易场景的跨境单证 AI 合规审查平台：上传发票、装箱单、原产地证、报关单 → 本地 OCR → LLM 结构化抽取 → RAG 检索规则条款 → 带条款引用的风险报告 → 多语种追问。设计集成 OCR、LLM、Embedding、Reranker 四类模型（满足 ≥2 类硬性要求）。

### 1.2 安全目标
1. 单证原件与商业敏感信息最小化出域，出域可审计。
2. 模型不可被单证内嵌指令或用户追问操控；输出可校验、可溯源、带 AIGC 标识。
3. 越权、滥用、篡改被拒绝、记录且可现场验证。
4. 提交前多工具自扫描 HIGH/CRITICAL 清零。

### 1.3 安全设计原则
纵深防御、最小权限、默认拒绝、数据最小化、零信任对待模型输入输出、全程可审计、安全与功能同代码。

### 1.4 总体安全架构
三层防护：**应用安全**（认证、RBAC、限流、入参校验、审计哈希链）→ **模型安全**（注入检测、提示隔离、输出校验、引用校验、AIGC 标识、AI 接口管控）→ **数据安全**（TLS、AES-256-GCM 信封加密、出域脱敏、RLS 租户隔离候选、保留期销毁）。模型调用经统一 `ai/` 客户端，业务不得绕过。

## 2. 资产识别与数据分级

| 资产 | 示例 | 级别 | 主要保护措施 |
|---|---|---|---|
| 单证原件 | 发票/报关单 PDF、图片 | 核心敏感 | AES-256-GCM 信封加密、不出域、保留期 |
| 个人信息 | 联系人、电话、邮箱、地址、证件号 | 敏感个人信息 | 出域前脱敏、最小保留 |
| 商业信息 | 单价、金额、银行账号、买卖方 | 商业秘密 | 脱敏占位、对象级授权 |
| 规则知识库 | 公开关税/原产地/禁限条款 | 公开 | 来源与版本记录 |
| 模型凭据 | 云端 LLM API 密钥、主密钥 | 机密 | 仅服务端环境变量，不入库不入仓 |
| 审计日志 | 操作与模型调用轨迹 | 重要 | 只追加 + 哈希链 + `/audit/verify` |

## 3. 威胁建模

### 3.1 数据流与信任边界
①浏览器 ↔ API；②API/Worker ↔ 云端 LLM（出域）；③单证内容 ↔ 提示词；④业务服务 ↔ 数据库（租户边界）。

### 3.2 STRIDE 分析

| 类别 | 威胁场景 | 对策 | 证据（代码侧） |
|---|---|---|---|
| S 仿冒 | 撞库、令牌重放 | Argon2id、失败锁定、短时 JWT、刷新轮换与令牌族作废 | `tests/test_auth.py` 等鉴权用例 |
| T 篡改 | 篡改审计/字段/原件 | 日志哈希链；字段版本化；原件 GCM + SHA-256 | `/audit/verify`；`test_m2_*` |
| R 抵赖 | 否认操作 | 全量审计（actor、角色、IP、trace_id、结果） | 审计 API + AuditPage |
| I 信息泄露 | 出域泄露、跨租户 | 出域脱敏；RLS 候选 + 应用层租户上下文；统一错误 | `test_m2_security`、`test_m2_audit_isolation`、`test_m2_tenant_context` |
| D 拒绝服务 | 刷接口、超大文件 | 滑动窗口限流、文件上限与魔数、token 配额、熔断 | `test_m2_limits`（429） |
| E 提权 | 合规员读全局审计；提示注入诱导 | RBAC + 对象级授权；模型无工具调用 | RBAC 矩阵测试；注入用例 |

### 3.3 OWASP Top 10 for LLM Applications（2025）映射

| 编号 | 风险 | 本系统场景 | 控制措施 |
|---|---|---|---|
| LLM01 | Prompt Injection | 单证藏指令；追问越狱 | 输入检测、数据区边界、系统提示服务端固定、输出 Schema；命中写审计 |
| LLM02 | Sensitive Information Disclosure | PII/商业信息出域 | 出域脱敏占位与服务端还原、输出敏感检测、映射不落库 |
| LLM03 | Supply Chain | 依赖/权重投毒 | 依赖锁定 + 自扫描流水线；模型官方源与哈希 **待补(证据)** |
| LLM04 | Data and Model Poisoning | 伪条款入库 | 规则库仅管理员可写、来源/版本、入库审计 |
| LLM05 | Improper Output Handling | XSS 或当指令执行 | Pydantic 校验、前端转义、CSP |
| LLM06 | Excessive Agency | 模型触发删除/改权 | 模型无工具调用，动作经 RBAC |
| LLM07 | System Prompt Leakage | 套取系统提示 | 系统提示不含密钥；输出检测片段 |

| LLM09 | Misinformation | 编造条款 | 规则先判；引用必须在 Top-5，否则降级人工复核 |
| LLM10 | Unbounded Consumption | 刷模型 | 用户/租户频率与日 token 配额、单次上限、熔断 |

## 4. 数据安全设计
- **4.1 传输安全**：对外 HTTPS（HSTS）；服务间内网。
- **4.2 存储安全**：原件 AES-256-GCM 信封加密，主密钥可轮换。待补(证据)：密文片段截图。
- **4.3 出域脱敏**：正则/词典替换为 `<PHONE_1>` 等；映射仅任务内存；计数入审计。证据：`test_m2_security` 脱敏/输出过滤用例。召回率评测集 **待补**。
- **4.4 租户隔离**：业务表 `tenant_id`；应用层强制租户上下文；PostgreSQL RLS **候选** + 启动 catalog/grant 漂移 gate（未宣称官方演示机 RLS 验收）。证据：`test_m2_tenant_context`、`test_m2_audit_isolation`、`test_m2_postgres_rls`（活库 opt-in）。
- **4.5 生命周期**：默认保留期与删除留审计。
- **4.6 数据来源合规**：规则库公开渠道并记录出处；演示单证为脱敏自制样例。

## 5. 模型安全设计
- **5.1 输入侧**：注入/越狱规则库 + 异常检测；追问场景可直接拒答。证据：`test_m2_security`。
- **5.2 提示隔离**：系统提示服务端固定；单证置于边界标记数据区。
- **5.3 输出侧**：Schema 校验、敏感与提示片段检测；SSE 完整缓冲后再发 delta。
- **5.4 可信与可溯源**：规则引擎先行；条款引用校验；`model_calls` 轨迹（不含明文提示）。
- **5.5 AIGC 标识**：显式「AI 生成，仅供参考」；隐式元数据 **待补(证据)** 导出样例。
- **5.6 AI 接口管控**：密钥仅环境变量；模型白名单；配额；熔断后 DeepSeek → 通义 → 本地 Qwen → 规则兜底。**真云端/本地 LLM E2E 待演示环境**，不得用 FakeLLM 冒充现场验收。
- **5.7 模型风险管理**：ISO/IEC 23894 循环；风险登记表见附录 B（待补）。

## 6. 应用安全设计
- **6.1 身份认证**：Argon2id；JWT 短时；刷新 Cookie HttpOnly+Secure+SameSite；登录锁定。
- **6.2 访问控制**：RBAC（admin / reviewer / auditor）+ 对象级授权；跨用户/跨租户固定 404/403。
- **6.3 输入与文件安全**：Pydantic；魔数；≤10MB/≤10 页；文件名不参与存储路径。
- **6.4 限流防刷**：Redis 滑动窗口（用户+IP）；Redis 异常 fail-closed 503；429 入审计。证据：`test_m2_limits`。
- **6.5 Web 防护**：CORS 白名单、安全响应头、ORM 参数化、统一错误。
- **6.6 审计日志**：登录/越权/上传/审查/追问/模型/注入/限流等；哈希链；`GET /audit/verify`。前端 AuditPage 已对接 OpenAPI 0.4.0。
- **6.7 安全开发与供应链**：`scripts/security-scan.sh` 并联 Semgrep、Bandit、gitleaks（含历史）、Trivy、pip-audit、npm audit；HIGH/CRITICAL 非零失败。M2 合并复核与后续工作区扫描均为 **CRITICAL=0 HIGH=0**（见 `reports/security/`）。
