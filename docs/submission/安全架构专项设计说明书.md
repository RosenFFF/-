## 1 资产、边界与威胁
保护原件、抽取字段、租户数据、模型调用凭据与审计记录。浏览器/API、任务执行、模型出域、数据库与本机运维是不同信任边界。主要风险为跨租户访问、提示注入、数据外泄、幻觉引用、配额耗尽、供应链与依赖故障。

## 3 模型风险与诚实呈现
D 的 L0 与 `llm_verified=true` 只证明 ASGI 单样例审查和简短追问成功。宽泛追问 MODEL_UNAVAILABLE 已定位并修复（71311f4）：原因是引用白名单只含本问 top-5 检索，模型引用报告自身发现的规则被判越界；现允许“检索 ∪ 本报告已引用且在语料中的规则”（上限 chat_max_allowed_rules=20），伪造/未知 id 仍拒绝。真实 DeepSeek 2 轮×5 问 10/10 成功（ASGI，小样本，非 P95）。引用校验未放宽为任意 id，安全过滤、超时与输出上限不变。

检索与重排是轻量回退，不是 BGE。备用云端与本地 LLM 仅为降级设计，未获本轮成功证据；S 实测 Ollama `models=[]`。F 的 L3/失败 UI 已合并，但使用替身数据库和开发服务器。浏览器生产构建与真实模型/PG/Redis 联合验收仍缺失。

## 4 运维与故障安全
PG、Redis、Ollama 在 S 中仅回环监听，角色认证/SELECT 1、Redis PONG 通过。PG 缺失目录恢复不等于历史数据完整性认证；缺失原因与自启保障未解决。故障时保留 RLS、租户和限流门禁；不得切 owner、SQLite/fakeredis 或 mock 后仍称真实验收。具体流程见《故障预案》。

## 5 测试与标准边界
D 默认回归 391 passed、3 skipped，DeepSeek opt-in 单独真实通过。S 388 passed、1 skipped 是较早独立恢复验证，非新增成功数。标准仅作为设计参照（GB/T 8567、GB/T 15532、ISO/IEC 25010 与 AI 风险管理等），条款映射、评测与认证未完成，不作合规认证宣称。

本分支执行 `scripts/security-scan.sh` 与独立 gitleaks；具体工具状态、缺失与扫描器错误以 `reports/security/` 及本轮文档更新记录为准，不用历史“零高危”冒充本次结果。
